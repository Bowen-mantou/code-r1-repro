## 一、Learned Verifier 完整设计空间

### 1.1 为什么是「生成式 6 分类」而不是别的（设计空间的每个分支）

| 候选设计 | 优缺点 | 我们的选择 |
|---------|--------|-----------|
| 回归头（输出 [0,1] 标量）| 需改模型结构、丢弃预训练语言建模能力 | ❌ |
| 二分类（对/错）| 信息量低（只知对错不知「差多少」）| ❌ |
| 判别式打分（RAG 风格）| 需要配对训练数据、泛化差 | ❌ |
| **生成式 k/N 分类** | 复用预训练语义（数字 token 天然有序）、零结构改造、k 的信息量适中 | ✅ |
| 打分 0-100 | 粒度太细、标注难（无法定义 73 分 vs 74 分）| ❌ |

**核心洞察**：「代码能通过几个测试」天然是 0-5 离散量（LCB 每题 5 测试）——把它建模成
生成式分类，等于**让奖励信号的语言模型化了**：verifier 的输出空间与它的预训练分布
对齐，这是它能用 1.5B 就达 ECE 0.0067 的根本原因。

### 1.2 校准数学的完整推导（面试能写公式）

**问题**：softmax 输出的概率 P(k) 不是真实正确率——LLM 天生过度自信。

**两级校准**：
```
Step 1 温度校准：P_T(k) = softmax(logits/T)
    T 在验证集上最小化 NLL 搜（T>1 平滑过度自信）
Step 2 Platt 校准：对聚合分数 V_raw = Σ k·P_T(k)/5 再做逻辑回归
    logit(V) = log(V/(1−V))
    V_cal = 1/(1 + exp(−(a·logit(V) + b)))
    我们的定稿：a=1.571, b=10.333（b 很大 = 原始 V 系统性偏低，需要大幅抬升）
```

**为什么需要两级**：温度保序（只改尖锐度），Platt 改偏移（b=10.33 说明模型的 V_raw
比真实正确率系统性偏低——「保守的模型」）。**保序性和偏移修正是两个独立的问题，
两个参数各管一个**。

**ECE 的完整定义**：
```
ECE = Σ_{b=1}^M (n_b/N) · |acc_b − conf_b|
分 M 桶，每桶算「平均预测置信度」vs「实际正确率」的差，按桶大小加权。
ECE=0.0067 的含义：「verifier 说 0.8 的代码，实际约 80% 通过」——误差 < 0.7%。
```

### 1.3 数据构造（零人工标注的闭环）

```
1. 从训练/评估题集采样 (题目, 代码) 对——代码来自各实验模型的 rollout（多样分布）
2. 沙箱执行：对每题的子测试集分别跑 → 得到真实 k（通过数）
3. 部分样本用「子集 k/N」标注：只跑 5 个测试中的子集，k 是子集通过数
   → 训练数据覆盖「部分正确」的中间态（比二分类多 4 倍信息）
4. 标签分布平衡处理（正确/错误/中间态混合）
```

### 1.4 推理路径的工程细节（面试追问点）

```python
# 取最后一个有效 token 的 logits（padding 场景的经典 bug 预防）
last_pos = enc["attention_mask"].sum(dim=1) - 1
logits = out.logits[torch.arange(len(texts)), last_pos]
digit_logits = logits[:, self.digit_ids]     # (B,6)，只取 "0".."5" 六个 token
probs = softmax(digit_logits)
v_raw = (probs * arange(6)).sum(-1) / 5      # 期望值而非 argmax
```
- **期望值 vs argmax**：V=0.73 比「预测 1 个数字」携带更多梯度信息——soft 分数是
  塑形信号的灵魂
- **截断策略**：prompt ≤1024 字符（题目头部信息量高）、代码取尾部 2048（关键实现在后半）

### 1.5 部署架构（Ray 单例 + 攒批的完整故事）

**三次架构演进**（每次都是显存/速度账逼出来的）：
```
v1：8 worker 各加载 verifier → 8×4GB → OOM（设计前没数调用方）
v2：Ray 命名单例 actor → 1 份模型共享 → 显存解决，但 per-sample 串行调用步耗时 51s
v3：actor 内 20ms 攒批窗口 → batch 推理 → 19.7s（3.6× 提速）
```
**面试句式**：「常驻服务的三个问题按顺序出现：实例数（单例）、调用开销（攒批）、
并发安全（ActorAlreadyExistsError 兜底）——顺序不能反，先解决实例数再谈优化。」

## 二、RG-OPD 门控完整解析

### 2.1 公式推导与直觉

```
g_i = I[(A_i > 0 ∧ L_T > L_S + δ) ∨ (A_i ≤ 0 ∧ L_T < L_S − δ)]

A_i  : 轨迹级奖励信号（我们：V_cal > 0.5 视为正）
L_T  : teacher 对整条轨迹的 log-lik = Σ_t log π_T(token_t | 前缀)
L_S  : student 同理
δ    : 置信裕度（我们 δ=0）
```

**为什么这个门合理（四个象限）**：
| | teacher 更确信（L_T > L_S）| teacher 更不确信（L_T < L_S）|
|---|---|---|
| **奖励正**（A>0）| ✅ 蒸：好轨迹 + teacher 认可 → 强化 | ❌ 不蒸：teacher 不认可的好轨迹（风格不同）——保护探索 |
| **奖励负**（A≤0）| ❌ 不蒸：teacher 认可的坏轨迹——**过滤 teacher 的错误信念** | ✅ 蒸：坏轨迹 + teacher 也否定 → 反向信号（负 KL 推离）|

**核心思想**：「verifier 定方向（轨迹好不好），teacher 定幅度（token 级差异）」
——两个信号各司其职，冲突时以 verifier 为准（不蒸）。

### 2.2 与相邻方法的关系（论文谱系，面试展示调研深度）

| 方法 | 门控方式 | 与我们的关系 |
|------|---------|-------------|
| 无条件 OPD（E5）| 无门控 | 基线——假设 teacher 无误 |
| RG-OPD（2607.04037）| sign-gate（我们复现的）| 轨迹级一致性门控 |
| SG-OPD（2606.09304）| token 级 sign-consistency + 分阶段 teacher 采样 | 更细粒度（token 级）+ 冷启动增强 |
| OPDVR（LeapLabTHU）| ReLU 门（verifier 定符号）| 更简单：正确轨迹非负、错误轨迹非正 |
| RWOPD（2605.13501）| reward-weighted 连续权重 | 软门控（V 加权）而非硬过滤 |

**我们实现的独特处**：① sign-gate 在 veRL low_var_kl 路径的原生实现；② gate frac
实时观测（v3）；③ fallback 容错（链路断时不崩、告警）；④ **在代码域 + 自蒸馏设置的
边界条件实测**（论文没测的设置）。

### 2.3 三版实现的迭代逻辑（bug 故事线）

```
v1：torch.as_tensor(NonTensorStack) → 空张量 (B,0) → RuntimeError: size 0 vs 10
    → 教训：容器类型转换前先确认 .tolist() 约定
v2：.tolist() 转换 + shape 校验 + fallback → 功能正确
    → 但「门控是否生效」无法观测
v3：加 gate frac 打印 → 观测到 0.10-0.18 → 铁证 + 失效分析的起点
```

### 2.4 失败机制分析（为什么 gate frac 只有 0.18 且无增量）

**三层原因（面试完整版）**：

1. **teacher=student 自蒸馏 → L_T vs L_S 是噪声比较**
   初始时两个模型完全相同，L_T−L_S 的符号由浮点噪声决定 → 随机砍掉一半轨迹。
   RG-OPD 论文的设置里 teacher 显著强于 student，这个比较才有语义。
2. **verifier 条件叠加 → 通过率 = 25% × 50% ≈ 12%**
   模型正确率 25%（V>0.5 的比例）→ 再乘噪声比较的 50% → 每批 1-2 条有效轨迹，
   梯度噪声淹没信号。
3. **已收敛模型上的扰动**
   E9p2 在 25.2 收敛带，蒸馏 KL 拉向「自己昨天的分布」只会偏离。

**可发表的结论**：「RG-OPD 门控的有效性依赖 teacher-student 能力差——这是原论文
未明示的隐含前提。在自蒸馏设置下，sign-gate 退化为噪声过滤器，通过率塌缩到 ~15%，
蒸馏无增量（LCB 24.8 vs 25.2）。」

### 2.5 如果重做门控实验（改进路线图）

| 改进 | 预期效果 | 依据 |
|------|---------|------|
| teacher 换 7B | L_T vs L_S 有真实语义 | RG-OPD 原设定 |
| δ 调负值（-0.1~-0.5）| 通过率提到 30-50% | 稀疏信号问题的直接解药 |
| 软门控（V^γ 加权替代硬 0/1）| 保留梯度连续性 | RWOPD/SG-OPD 的中间路线 |
| Direct-OPD shift 迁移 | 蒸「RL 前后的策略差」而非最终策略 | 2607.05394：shift 才含奖励信息 |
| 阶段拉长到 2ep | 给稀疏信号积累时间 | 我们的 1ep 可能欠训练 |

## 三、创新性论证（简历/面试的「贡献点」表述）

   + 双校准达到 ECE 0.0067，构建了「verifier 分数可信 → 可作奖励信号」的完整证据链

   负结果闭合了「顺序不影响终点」的完整证据
