# 必背手册：Code-R1 项目面试速记（08）

> 面试前 5 分钟过一遍。★ = 必背，★★ = 背到能默写。

## ★ 一、项目一句话（30 秒电梯陈述）

「我在 3B 代码模型上独立完成了五类训练信号的对照研究——GRPO 执行奖励、OPD 蒸馏、
手写 PRM、学习型 verifier 及其门控蒸馏，共 6 个模型；最优 LiveCodeBench 25.2 超过
官方 7B 基线；期间发现并修复了一个让两轮实验结论作废的信号链路缺陷。预算 ¥400
全程自管理。」

## ★★ 五、绝对不能说的话（口径纪律五条）

1. **不能说「verifier 提升了 GRPO」**——E7/E9p2 的 verifier 信号链路断，从未生效；
   25.2 是纯 GRPO 2ep 的结果。正确说法：「verifier 奖励注入是已修复但未重跑的设计，
   生效验证只发生在门控场景（gate frac 0.18）」
2. **不能说「手写 PRM 有用」**——E2 21.0 全维度垫底
3. **不能说「warm-start 有效」**——E9p2=E7 证明起点不改变终点
4. **不能说「门控蒸馏有效」**——自蒸馏设置下无增量（24.8），只说「边界条件发现」
5. **不能说「GRPO 比 OPD 强」**——25.2 vs 24.7 在噪声内，正确说法是「打平」

## ★ 六、三个必讲故事（各 1 分钟版）

1. **链路 bug**：分数巧合起疑（E7=E9p2 小数点后 15 位相同）→ 逐跳追数据流
   （extra_fields 不展平）→ 一行顶层提取修复 → gate frac 铁证。核心信息：
   「静默降级比崩溃更危险——不报错 ≠ 没问题」。
2. **门控边界条件**：RG-OPD 在自蒸馏下 gate 通过率塌缩到 0.18、无增量——界定
   原论文未明示的「teacher 必须强于 student」前提。核心信息：「负结果划定边界」。
3. **warm-start 无关**：E9p2=E7=25.2 与论文 2606.09059 独立互证。核心信息：
   「起点决定路径不决定终点」。

## 七、高频追问标准答法（10 问，各 2-3 句）

1. **为什么 3B 全参**：对齐 Code-R1 论文口径；3B 全参在预算上是「大模型 LoRA 的
   等价物」，RL 的行为改变需要全参表达力。
2. **为什么用 KL**：防策略崩塌的保险丝；显存代价被 ref offload + k3 单样本估计器
   消化（58.6GB 峰值已含 KL 实测）；E1 的 4ep 退化反证其必要性。
3. **为什么 GRPO 不用 critic**：省一半模型显存；组均值是无偏 baseline；代码任务
   轨迹长度集中（2048 截断），长程短板不触发。
4. **verifier 为什么 1.5B 不是 3B**：显存（共卡 4GB）、速度（rollout 关键路径）、
   任务简单（ECE 0.0067 证明够用）。
5. **λ_v 为什么 0.1**：结果主导防黑客；RWOPD/PASS 论文警告过程信号占比过高有害；
   保守默认。
6. **为什么纯 OPD 而不是 GRPO+OPD 混合**：先隔离单变量再谈组合；SeqBeatsJoint 也
   说并行融合劣于串行。
7. **数据从哪来**：训练 code-r1-lc2k（2k 题）；评估三层难度（evalplus/LCB/
   CodeContests）；verifier 标注零人工（沙箱执行）。
8. **怎么保证口径**：LCB 880 题 main 冻结版 + sha256 对账；撞顶重跑保证生成口径；
   坏行报错不静默跳过。
9. **预算怎么管**：无卡预演一切（¥0.1/hr）、GPU 只跑验证过的、watchdog 自动关机、
   MISTAKES 账本（可避免浪费 ~¥25）。
10. **下一步做什么**：阶段 A（verifier 奖励修复版，¥45）+ 7B teacher 门控（E10
    OPDVR 原味）——信息价值递减原则排序。
