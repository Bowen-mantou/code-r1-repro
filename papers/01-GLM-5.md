# GLM-5: from Vibe Coding to Agentic Engineering（arXiv 2602.15763，智谱/清华，2026-02）

**一句话**：744B MoE（40B active）的完整训练配方公开——多阶段 RL + **On-Policy Cross-Stage Distillation** 解决能力遗忘。

## 核心发现

1. **多阶段 RL 的能力退化问题**：Reasoning RL → Agentic RL → General RL 顺序优化不同目标时，
   **先前获得的能力会累积退化**（在 General RL 阶段模型「忘记」推理/代码能力）。
2. **传统解法（混 SFT 数据）的缺陷**：off-policy 的 SFT 对全部 token 均匀施加修改力，
   破坏模型原有知识结构 → 遗忘。
3. **解法：On-Policy Cross-Stage Distillation（OPD）作为最后一阶段「能力恢复」**：
   - Teacher = 前序各阶段的最终 checkpoint（SFT 阶段、Reasoning RL 阶段、General RL 阶段）
   - 数据 = 学生自己 on-policy 生成的轨迹（纠错发生在模型实际行为分布上，避免 exposure bias）
   - **蒸馏信号转化为 advantage**：
     ```
     Â_{i,t} = sg[ log(π_teacher(y_t|x, y_<t) / π_student(y_t|x, y_<t)) ]
     ```
     sg = stop-gradient。学生生成的 token 若 teacher 也给高概率 → 正 advantage（强化）；
     学生概率超过 teacher → 负 advantage（惩罚）。token 级稠密修正信号。
   - **GRPO group size = 1**（advantage 直接来自 teacher-student gap，不需要大组内相对估计）
   - batch size 1024，teacher logits 走推理引擎——SFT/RL/蒸馏统一进一个 RL 引擎（slime 框架）

## 对我们的启示（03-code-r1）

- **用户新方案的阶段 3 正是这个**：teacher=前序阶段模型，advantage=log ratio。
  veRL 的 OPD low_var_kl 是它的近似实现（E5 配方已验证）。
- 关键细节：teacher 用「前序最优模型」而非固定基模——即阶段 3 的 teacher 应是阶段 2 产物
  或阶段 1 产物，不是 Qwen 基模。
- 多阶段顺序优化会遗忘 → 我们的 E9（蒸馏先行）+ 阶段 3（在线蒸馏恢复）的组合
  正是「蒸馏-强化-恢复」闭环，与 GLM-5 的完整管线同构。
